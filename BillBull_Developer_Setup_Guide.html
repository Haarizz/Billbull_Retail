BillBull Retail — Developer Setup Guide

Updated 19 Oct 2026 · Repository: github.com/Haarizz/Billbull_Retail

Install JDK 17, Maven 3.9, Node.js 22, PostgreSQL 17 and Git, clone the repo, then start the backend on port 8080 and the web app on port 5173.

Overview

When you finish this guide you'll have three things running against a local PostgreSQL database: the backend on http://localhost:8080, the Retail web app on http://localhost:5173 and, if you want it, the standalone POS till on http://localhost:5174/pos/. Work branches off main.

FolderWhat it isStackNeeded to run?
billbull-backend/REST API, business logic, DB schemaSpring Boot 3.5.9, Java 17, Maven, PostgreSQL, FlywayYes
billbull-frontend/npm workspace: Retail app (src/), standalone POS (apps/pos/), shared code (packages/shared/)React 19, Vite 7, Tailwind v4Yes
tools/pos-print-agent/Windows tray app that drives USB / Bluetooth / Windows-queue thermal printersNode.js, packaged with pkgOnly for local receipt printing
tools/pos-parity/Headless-Chrome harness that compares the embedded and standalone POSNode.jsNo (QA only)
k8s/, docs/, root .md/.htmlDeployment manifests and architecture notes—No

The browser calls the backend under /api, and the backend keeps all data in PostgreSQL. The print agent runs as its own local process, and the browser reaches it on 127.0.0.1:19777.

OS: the project is developed on Windows 10/11, and macOS and Linux work with the same commands. The POS print agent runs on Windows only.

Check your machine

Run the checks below before installing anything. If a check shows "not recognized" or the wrong version, install or fix that tool using Install what's missing.

One-shot check script

The scripts print every version on one screen and mark each line OK, OLD or MISSING. Copy the one for your OS and paste it into a terminal.

function Check($name, $cmd, $pattern, $min) {
  try {
    $out = (& $cmd[0] $cmd[1..($cmd.Length-1)] 2>&1 | Out-String).Trim()
    if ($out -match $pattern) {
      $v = [version]($Matches[1])
      $status = if ($v -ge [version]$min) { "OK     " } else { "OLD    " }
      "{0} {1,-11} {2}  (need {3}+)" -f $status, $name, $v, $min
    } else { "?       {0,-11} {1}" -f $name, ($out -split "`n")[0] }
  } catch { "MISSING {0,-11} not found on PATH" -f $name }
}

Maven manual install (Windows)

  1. Download apache-maven-3.9.x-bin.zip from maven.apache.org/download.cgi.
  2. Extract it to C:\Program Files\Apache\maven, so that C:\Program Files\Apache\maven\bin\mvn.cmd exists.
  3. Add it to your user PATH (PowerShell): 
    [Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User") + ";C:\Program Files\Apache\maven\bin", "User")
  4. Open a new terminal and run mvn -v.

Set JAVA_HOME and PATH (Windows)

Skip this step if the JDK installer already set them. Change the folder to match where your JDK 17 is installed:

[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Eclipse Adoptium\jdk-17.0.12.7-hotspot", "User")
[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User") + ";%JAVA_HOME%\bin", "User")

Put psql on PATH as well, so you can run it from any terminal:

[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User") + ";C:\Program Files\PostgreSQL\17\bin", "User")

As a GUI alternative: Start → "Edit the system environment variables" → Environment Variables → edit Path under User variables.

Several JDKs can coexist on one machine. Maven uses whichever one JAVA_HOME points to, and the java command uses the first one on PATH. Point both at JDK 17.

Clone the repository

Clone main over HTTPS into a short path such as C:\dev. The repo is public, so cloning needs no credentials. Pushing does.

  1. On Windows only, enable long paths once, because some node_modules paths are longer than 260 characters: 
    git config --global core.longpaths true
  2. Clone the repo and enter it: 
    git clone https://github.com/Haarizz/Billbull_Retail.git
cd Billbull_Retail
    If your GitHub account has an SSH key, use git@github.com:Haarizz/Billbull_Retail.git instead.
  3. Set your identity for commits: 
    git config user.name "Your Name"
git config user.email "you@example.com"
  4. To work on a feature, branch from main. The repo has 180+ branches, which git branch -r lists. 
    git checkout -b feature/my-change

GitHub's "Code → Download ZIP" also works for a read-only copy, but without Git you can't use git pull or branches.

Database setup

Create an empty PostgreSQL database named testdb, owned by user postgres with password admin. Those are the dev defaults in application.properties, so the backend connects without any config changes.

  1. Create the database: 
    psql -U postgres -h localhost -c "CREATE DATABASE testdb;"
    To use pgAdmin instead, go to Databases → Create → Database and enter the name testdb.
  2. Choose how to fill it:
OptionWhen to useHow
A. Empty database (recommended for a first run)You want a clean start with no client dataDo nothing. The backend builds the schema on its first boot.
B. Restore the sample dumpYou want realistic products, sales and ledgerspsql -U postgres -h localhost -d testdb -f testdbbillbull.sql
The dump is 11 MB and was taken from PG 17.6. Restoring it needs psql 17.6+ because of its \restrict line.

What happens on first boot: Flyway runs first, applying the scripts from V1__baseline.sql up to V120__… in billbull-backend/src/main/resources/db/migration. Its guarded scripts skip tables that don't exist yet. Hibernate (ddl-auto=update) then creates every table. Last, the startup seeders insert roles, permissions, the chart of accounts, a "Main Branch" and the admin user.

This database is for you alone. Never point a dev backend at a client's production database. The @SpringBootTest tests also write to whatever database is configured.

Run the backend

From billbull-backend/, set an admin password and run mvn spring-boot:run. The API is up on port 8080 once the log prints Started BillbullBackendApplication.

  1. Set the first admin password. The backend reads it only when no admin user exists yet. 
    # PowerShell
$env:ADMIN_INITIAL_PASSWORD = "ChangeMe123!"

# Git Bash / macOS / Linux
export ADMIN_INITIAL_PASSWORD='ChangeMe123!'
    If you skip this step, the console prints a random 16-character password once, after INITIAL PASSWORD:. Copy it.
  2. Start the app: 
    cd billbull-backend
mvn spring-boot:run
    The first run downloads dependencies into ~/.m2 and takes several minutes. On later runs you can add -o to work offline.
  3. Confirm the log shows Started BillbullBackendApplication and Created default ADMIN user (username: admin).

Other DB credentials: pass them on the command line. application.properties is committed, so don't put local credentials in it.

mvn spring-boot:run "-Dspring-boot.run.arguments=--spring.datasource.url=jdbc:postgresql://localhost:5432/mydb --spring.datasource.username=postgres --spring.datasource.password=secret"
Environment variableDefaultPurpose
ADMIN_INITIAL_PASSWORDrandom, printed oncePassword for the seeded admin user
JWT_SECRETdev placeholderSigns login tokens. Set a long random value anywhere other than dev.
JWT_EXPIRATION86400000 (24 h, ms)How long a login token lasts
PLAYWRIGHT_BROWSERS_PATHPlaywright per-user cacheWhere the PDF renderer's Chromium is stored

Client profiles: files such as application-demo.properties, -geebu and -hilite each point at one client's own database and port. Use one only when you have a matching local database. For example, mvn spring-boot:run -Dspring-boot.run.profiles=demo uses port 8083 and the database billbull_demo.

PDF generation: the first PDF export downloads Playwright's Chromium automatically (about 150 MB). On a machine without internet access, pre-install it:

mvn exec:java -e -Dexec.mainClass=com.microsoft.playwright.CLI -Dexec.args="install chromium"

Run the frontend

In a second terminal, go to billbull-frontend/ and run npm install, then npm run dev. Open localhost:5173 and sign in as admin.

  1. Install dependencies once. Because the folder is an npm workspace, this one command installs the Retail app, apps/pos and packages/shared. 
    cd billbull-frontend
npm install
    To install exactly the versions package-lock.json pins, use npm ci instead.
  2. Start the Retail app: 
    npm run dev
  3. Open http://localhost:5173 and sign in as admin. Then change the password under My Profile.
  4. The POS till inside the Retail app is at /sales/pos. To open it you need a POS terminal and an open session, both created from the app's POS settings.
The dev API address is set in billbull-frontend/.env.development (VITE_API_BASE_URL=http://localhost:8080). Keep the Retail dev server on port 5173, because it's the only localhost origin in the backend's CORS list (config/CorsConfig.java).

Standalone POS (optional): npm run dev:pos serves the till at http://localhost:5174/pos/ and proxies /api and /uploads to the backend. Read docs/standalone-pos/ARCHITECTURE.md first.

POS print agent (optional)

You only need the agent to print receipts on a USB, Bluetooth or Windows-queue printer. The backend drives network (IP) printers directly.

  1. Install and run the agent from source (Windows): 
    cd tools/pos-print-agent
npm install
node tray.js
    To run it without the tray icon, use node server.js. Either way it listens on http://127.0.0.1:19777.
  2. Bind each printer to a protocol. Agent 0.7.0 refuses any printer that hasn't been set up locally. 
    node server.js --set-printer "<Windows printer queue name>" escpos
    For Zebra label printers, use zpl instead of escpos. The tray menu can do the same thing.
  3. Pair the browser under POS → Devices. The pairing token is stored in that browser's localStorage, so pair once in each browser.
  4. To run the agent's tests, use npm test in the same folder.
Don't run --stop, npm run build or npm run build:installer on a machine that's using an installed BillBullPrintAgent.exe. --stop ends every running agent in the session, and the builds overwrite dist/ and installer/output/. For security and pairing details, see docs/standalone-pos/PRINT_AGENT_SECURITY.md and tools/pos-print-agent/SECURITY.md.

Troubleshooting

Most first-run failures come from one of three things: the wrong Java or Node version, a database the backend can't reach, or the frontend running on a port the backend doesn't allow.

SymptomCauseFix
mvn / node / psql "is not recognized"The tool isn't installed or isn't on PATHSee Install what's missing, then open a new terminal
invalid target release: 17Maven is using an older JDKPoint JAVA_HOME at JDK 17. mvn -v must show Java 17.
Connection to localhost:5432 refusedThe PostgreSQL service is stoppedStart it. On Windows: Start-Service postgresql-x64-17 (admin PowerShell).
password authentication failed for user "postgres"Your Postgres password isn't adminPass --spring.datasource.password=… as shown in Run the backend
database "testdb" does not existThe database hasn't been createdCREATE DATABASE testdb;
Port 8080 was already in useAnother app is using 8080Stop that app, or start the backend with --server.port=8081 and point VITE_API_BASE_URL at 8081
Can't log in and no admin password is knownThe admin user was created on an earlier run, or you restored the dumpIf you restored the dump, ask the team for its credentials. On a fresh DB, drop and recreate testdb, then restart with ADMIN_INITIAL_PASSWORD set.
CORS error in the browser consolePort 5173 was busy, so Vite moved to 5174 or higherFree port 5173 and restart npm run dev
Standalone POS (5174) says "Invalid username or password"The backend returns 403 because the 5174 origin isn't on its allow-listFor now, use the embedded till at /sales/pos on port 5173
Vite requires Node.js version 20.19+Node is too oldInstall Node 22 LTS
Filename too long (Windows)Windows' 260-character path limitRun git config --global core.longpaths true and clone into a short path such as C:\dev
javac bad class file during mvn testThe IDE's Java tooling wrote a corrupt .class file into target/classesDelete that one .class file and rerun the tests
PDF export hangs or fails the first timeChromium is still downloading, or the machine is offlineWait for the download to finish, or pre-install Chromium (see Run the backend)
unrecognized command \restrict while restoringpsql is older than 17.6Upgrade the PostgreSQL client tools to 17.6+
